# 📅 November 2026

## ✨ Improvements

- **New Colours and a Real Dark Mode**  
  The web client takes on the colours of the time cockpit website: a navy menu bar, Harbor Blue for buttons, links and table headers, and calm, cool greys. The page is a dimmed white and the text a soft dark grey, which is easier on the eyes over a long working day. Dark mode now has colours of its own instead of inverting the page, so images, charts and timesheet colours look the same in both modes. Under **Appearance** in the user menu, choose **Light**, **Dark** or **System**; **System**, the default, follows the setting of your operating system.

- **Calmer Motion**  
  The **load all** button no longer flashes red and white; it is highlighted with a soft yellow tint instead. If your operating system is set to reduce motion, the web client switches animations and transitions off; loading indicators keep turning slowly.

- **Lists, Forms and Dashboards in the New Design**  
  The commands of a list and its full-text search now share one row below the filter: commands on the left, the number of items and the search field on the right. The search field is always visible. Forms have underlined tabs and a quiet action bar with the main action in blue. Dashboard widgets have a blue line under their title instead of a shadow.

- **Calmer Time Sheet Calendar**  
  The day headers of the Time Sheet Calendar are light with a blue line instead of a solid blue band; today is underlined. The text of a timesheet is dark or white, whichever reads better on its colour, so light formatting-profile colours such as yellow stay readable.

- **Outlook Appointments Stay Visible**
  Outlook appointments in the Time Sheet Calendar now have only an outline, while timesheets are filled, so the two are easy to tell apart. A timesheet no longer hides the appointment under it: the text moves to the free part of the appointment, and a fully booked appointment keeps a narrow strip at its right edge. Showing timesheets and appointments side by side remains available. See [Working With Outlook Appointments](../timesheet-calendar/outlook-appointments.md).

- **Clearer Text in Calendar Items**
  The description of a timesheet or appointment now comes first; time and duration are smaller and lighter. An item with room for only one line shows its description and duration instead of the start and end time. Blocks of the **Proposal** lane show the topic and duration; the time remains in the tooltip.

- **New Typeface**  
  The web client now uses Mulish, the typeface of the time cockpit website and time cockpit sidekick. Text is one step larger (13 instead of 12 pixels), and menus, headings, tabs, and dialog titles use sentence case instead of capital letters. In the timesheet calendar, the date, the day headers, and the start time and duration of timesheets are larger and bolder, so they stand out from the descriptions. Date and time fields in forms are wider, so the full date stays visible.

- **Search in the Signals Pane**  
  The right pane of the Time Sheet Calendar can search all signals of the day from time cockpit sidekick: window titles, applications, file paths, keywords, Wi-Fi networks and AI sessions. A ruler shows when the matches occurred; with a selection you can search the selection or the whole day. The search replaces the search field of the keywords. See [sidekick Signals in the Time Sheet Calendar](~/doc/sidekick/calendar-signals.md#searching-the-signals).

- **Calmer Signals Pane**
  The sections of the right pane now show at first what a booking needs, and the bars look the same everywhere: a thin bar in each row and at most one bar per section that shows a split. Colour stands for a project or an application only. **Window titles** and **Applications** are one section with the switch **By title** and **By application**, and **AI** shows the time per project, with the cost in the details. The sliders icon in the band of a section shows its details; **Ctrl** + mouse wheel changes how many rows a section shows. See [sidekick Signals in the Time Sheet Calendar](~/doc/sidekick/calendar-signals.md#signals).

## 🐛 Bug Fixes

- **Unit Column on Invoice PDFs**  
  Since the ZUGFeRD update, the unit column of invoice PDFs stayed empty. It shows the unit name again. Units have a new field **E-Invoice Unit Code** that holds the UN/ECE Recommendation 20 code written to the ZUGFeRD data, so kilometers are no longer reported as hours. The shipped units "h" and "km" received `HUR` and `KMT`; check your own units in the [units list](https://web.timecockpit.com/app/lists/entity/APP_Unit). See [Invoicing](~/doc/project-time-tracking/billing.md#unit) (#6041).

- **Reverse Charge Note on Invoice PDFs**  
  Since the ZUGFeRD update, invoice PDFs showed the reverse charge note intended for customers outside the EU even when the country of the invoice is an EU member. The note matches the country again.

- **Timesheets Created by AI Assistants**  
  Through the local MCP server (`OnCockpit.Admin.exe --mcp`), creating a timesheet failed every time, and changing an object's relation through `create_object` or `update_object` could fail the same way. Both now work. When time cockpit rejects an object because a validation rule is not met, for example a booking on a closed project, both MCP servers return the rule's message and the fields it concerns (for example `APP_ProjectUuid`) instead of a generic error, so the assistant can tell you what to correct. The local MCP server now also labels entities and fields in your language, as the hosted server does. Invoices can now also be created through the local MCP server, and objects created or changed by an AI assistant get the same default values as in the web form on both servers, for example an invoice's address from the project's customer. See [AI Agents and the time cockpit MCP Server](~/doc/mcp/overview.md).

- **Valid ZUGFeRD Data**  
  The ZUGFeRD data embedded in invoice PDFs failed schema validation because the delivery block was missing. It now contains the delivery date (the end of the service period, otherwise its start, otherwise the invoice date), the e-mail addresses of the company and the customer as electronic addresses, and the payment terms "Zahlbar netto" when a payment target without discount is set.

## 🛠 Notes for Customizers

These changes affect customers who maintain their own data model, lists, forms, or actions.

- **Chart Fonts in Dashboards**  
  Chart texts use the web client's font unless the dashboard configuration sets a `font`. Configurations that name `Roboto` now show the browser's default sans-serif font, because the web client no longer loads Roboto. Remove the `font` setting, or name `'Mulish Variable'` in it. See [Dashboards](~/doc/data-model-customization/dashboard.md#chart).

- **Default Colours of Charts and Formatting Profiles**  
  Charts without their own `seriesColors` and formatting-profile values without a stored colour use a new set of ten colours that stay distinguishable for people with colour-vision deficiencies, with their own values in dark mode. Charts and timesheets that relied on the previous automatic colours therefore change colour. Colours that are stored explicitly stay as they are.

- **Invoice Report Data**  
  The `InvoiceDetails` dataset that `APP_CreateInvoiceReportAction` passes to the invoice report contains the field `Unit` (unit name) again, plus `EInvoiceUnitCode`. `UnitCode` (the unit's code) stays available. The `Invoices` dataset contains `IsEuMember` again, next to `CustomerIsEuMember`. Customized copies of the invoice report that use `Fields!Unit` or `Fields!IsEuMember` work again without changes.
