# AGENTS.md

Agent-facing guide for this repository. Works with Claude Code (via `@AGENTS.md` in `CLAUDE.md`), Codex, Cursor, Copilot and similar tools. Keep it short; put long-form standards in `specs/`.

## What this repo is

The DocFX source for <https://docs.timecockpit.com>, the product documentation of time cockpit (time tracking SaaS).

| Path | Purpose |
|------|---------|
| `doc/**` | All product documentation as Markdown, one folder per topic. Main navigation: `doc/toc.yml`. |
| `api/` | API reference YAML, generated by DocFX from `../Binaries/TimeCockpit.Data*.dll`. Do not edit by hand. |
| `templates/modern/` | Verbatim copy of the docfx 2.78.2 `modern` template (source maps removed). Vendored because the build pipeline uses an old docfx without it. Never edit; upgrade path in `templates/README.txt`. |
| `tctemplate/` | Custom layer on the DocFX `modern` template: `public/main.css` (brand tokens, fonts, navbar), `public/main.js` (options, Mermaid zoom), `layout/_master.tmpl` (copy of the modern layout plus canonical/hreflang tags, re-diff on docfx upgrades). |
| `specs/` | Planning notes and content standards, not published. |
| `tools/GenerateLlmsTxt/` | PowerShell script that generates `llms.txt` and `llms-full.txt`. |
| `tools/GenerateRedirects/` | C# console app that maintains IIS redirect data. |
| `App_Code/`, `App_Data/`, `web.config` | IIS hosting and URL redirects. Maintained manually. |
| `_site/` | Build output. Gitignored, never commit. |

Content language is English. Hub pages (`doc/for-users.md`, `doc/for-developers.md`) and role FAQs (`doc/*-faq.md`) sit at the top of `doc/`.

## Build and preview

CI is the classic (non-YAML) Azure DevOps build pipeline `TimeCockpit.Documentation-CI`, defined in the Azure DevOps UI, not in this repo. Its steps: DocFx task on `docfx.json`, then `tools\GenerateLlmsTxt\generate-llms.ps1` (PowerShell task), then Archive `_site`, then Publish Artifact `site`. Any change to the build order must be made there as well. The DocFx task runs an old docfx (NuGet `docfx.console`, ≤ 2.59) that does not ship the `modern` template; that is why `docfx.json` references the vendored `templates/modern` by path, `tctemplate/token.json` carries the newer translation keys and `tctemplate/toc.json.*` generate the `toc.json` files the modern navigation loads. Do not use template features that need a newer docfx without checking docs-dev first. Locally, always build with the wrapper script, never with a bare `docfx` call:

```powershell
.\build.ps1                 # docfx metadata + build, then llms/markdown publish
.\build.ps1 -SkipMetadata   # no ../Binaries needed, skips API reference generation
.\build.ps1 -Serve          # additionally starts a local preview
```

`build.ps1` first runs `tools\GenerateSiteIndex\generate-site-index.ps1` (regenerates the committed `doc/site-index.md`, a server-rendered link list of every page for crawlers that do not execute the JavaScript navigation; never edit that page by hand), then `docfx docfx.json`, then `tools\FixSitemap\fix-sitemap.ps1` (rewrites sitemap `lastmod` with each page's last Git commit date; needs full history, a shallow clone falls back to the build time) and then `tools\GenerateLlmsTxt\generate-llms.ps1`. The second step regenerates `llms.txt` / `llms-full.txt` and copies `doc/**/*.md` into `_site`. The raw `.md` files are not part of the regular DocFX output, but `llms.txt` links to them, so a deploy without this step yields 404s for every Markdown link.

`llms.txt` and `llms-full.txt` are generated **and** committed. Never edit them by hand. IIS additionally needs a `.md` MIME mapping in `web.config` (`text/markdown; charset=utf-8`) to serve the files.

## Content conventions

- Every page starts with front-matter containing `title` and `description`. The description feeds `llms.txt` and the meta description, so make it a real one-sentence summary of at most 155 characters; quote it when it contains a colon. Optional keys: `faq: true` (page is an FAQ, every `###` question becomes schema.org FAQ markup), `og_image: name.png` (social preview image under `images/`, 1200x630, default `og-default.png`), `_noindex: true` (keeps the page out of search engines).
- Exactly one H1 per page (the `#` heading right after the front matter); sections start at `##`.
- Cross-folder links use `~/doc/...` (for example `[TCQL Overview](~/doc/tcql/overview.md)`). Never use `../` relative paths.
- File, folder and image names are kebab-case. Article images live in an `images/` folder next to the article (for example `doc/mcp/images/`).
- A new page must be added to `doc/toc.yml`, otherwise it is unreachable from navigation.
- Use DocFX alerts: `> [!NOTE]`, `> [!TIP]`, `> [!WARNING]`.
- Release notes are one file per month: `doc/release-notes/YYYY-MM.md`.
- Pages under `doc/mcp/` carry a "Preliminary documentation" warning banner. Keep it until the feature is released.
- Videos are consent-gated. Never paste a raw YouTube/Vimeo iframe. Use `<div class="tc-video" data-youtube="ID" data-title="..." data-poster="images/video-posters/ID.jpg"></div>` (or `data-vimeo="ID"`); `tctemplate/public/main.js` renders a local poster/placeholder until the visitor accepts "External Media" in the cookie banner. Store posters locally, never link a third-party thumbnail.
- Privacy: Google Analytics is loaded only after consent (Silktide banner configured in `tctemplate/layout/_master.tmpl`); Simple Analytics is cookieless and always on. Do not add other third-party scripts, fonts or embeds without a consent gate.
- Links to the marketing site are absolute (`https://www.timecockpit.com/features/...`, `https://www.timecockpit.com/blog/...`). Verify the slug exists before linking.
- UI navigation paths follow the real app modules: "Management" (not "Data Exchange"), "User" (not "Employee Time Tracking"). See `specs/ai-generated-content.md`.

## Accuracy rules

This documentation is a source of truth for customers and for AI assistants (llms.txt, context7). Wrong details are worse than missing details.

- Never invent TCQL functions, entities, properties, lists or actions. Only reference TCQL functions documented under `doc/tcql/`, and only `APP_*` / `SYS_*` names that exist in the data model.
- Code samples must be tested or copied from working code. Include the scenario and the expected result.
- If you are not sure a feature exists or behaves as described, leave it out or ask, rather than guess.
- Detailed standards, templates for entity/list/workflow pages and past lessons learned: `specs/ai-generated-content.md`.

## Do not touch

- `_site/`, `obj/`, `_exported_templates/` (build output)
- `api/**.yml` (generated)
- `llms.txt`, `llms-full.txt` (generated, regenerate via script)
- `App_Code/`, `App_Data/`, `web.config` (IIS hosting, changed manually by the owner)

## Agent workflow and delegation

- **Fable** (main session): high-level exploration, requirement refinement, planning, and final review of the result.
- **opus-implementer** (subagent, defined in `.claude/agents/opus-implementer.md`): mechanical execution of an approved plan, writing and editing pages, updating `doc/toc.yml`, running the build and the llms script, and reporting build errors verbatim.

Plan first, then hand the concrete file-level changes to the implementer, then review.
