# Mai 2017

## Bereich für Signaldetails ausblenden

Wenn Sie die Signale des time cockpit Signal Trackers nicht zum Buchen verwenden, nimmt der Bereich für Signaldetails am rechten Bildschirmrand dem Kalender viel Platz weg.

![Kalender mit Bereich für Signaldetails](/doc/release-notes/images/2017-05/calendar-with-signals.png "Kalender mit Bereich für Signaldetails")

In der neuen Version können Sie den Bereich für Signaldetails ausblenden. Wählen Sie im Menü Plugins:

![Plugins](/doc/release-notes/images/2017-05/plugins.png "Plugins")

Im Bereich Signale der Plugins finden Sie den neuen Eintrag Signal Tracker. Schalten Sie ihn aus, indem Sie den Schalter nach links schieben:

![Signal-Tracker-Plugin](/doc/release-notes/images/2017-05/signal-tracker-plugin.png "Signal-Tracker-Plugin")

Wenn Sie zum Zeiterfassungskalender zurückkehren, wird der Bereich für Signaldetails nicht mehr angezeigt:

![Kalender ohne Bereich für Signaldetails](/doc/release-notes/images/2017-05/calendar-without-signals.png "Kalender ohne Bereich für Signaldetails")

## ScriptingException für Aktionen

Bisher wurde empfohlen, Fehler in Aktionen durch Auslösen einer `ValidationException` zu behandeln. Der Text der Exception wurde in einer MessageBox angezeigt. Beim Einsatz einer `ValidationException` gibt es jedoch ein großes Problem: Sie wird so behandelt, als wäre die Aktion erfolgreich ausgeführt worden. Wird ein Parameterformular angezeigt, wird das Formular geschlossen. Wird die Aktion in bearbeitbaren Listen verwendet, werden alle Benutzereingaben zurückgesetzt.

In der neuen Version bieten wir für diese Szenarien eine neue `ScriptingException` an. Die `ScriptingException` lässt Parameterformulare geöffnet und setzt Benutzereingaben in bearbeitbaren Listen nicht zurück. Damit das funktioniert, muss die Aktion synchron ausgeführt werden. Andernfalls ist das Parameterformular möglicherweise bereits geschlossen, wenn die `ScriptingException` im Code der Aktion erreicht wird.

![Aktion synchron ausführen](/doc/release-notes/images/2017-05/synchronous-action.png "Aktion synchron ausführen")

Die `ScriptingException` bietet mehrere Überladungen:

```cs
 public ScriptingException(string message)
 public ScriptingException(string message, Exception innerException)
 public ScriptingException(string title, string message)
 public ScriptingException(string title, string message, Exception innerException)
 ```

## Fehlerbehebung: Fehlerbehandlung in der Web API

In den letzten Versionen haben wir oft einen allgemeinen „Internal Server Error“ angezeigt, wenn in unserer Web API eine Exception aufgetreten ist, statt Informationen über den tatsächlichen Fehler zu liefern. Das ist besonders ärgerlich, wenn Sie eigene Listen- und Formulardefinitionen für time cockpit erstellen, weil es Szenarien gibt, in denen Listen oder Formulare im Vollclient funktionieren, im Web-Client aber nicht. Eine häufige Fehlerursache ist nicht signierter Code, der nur im Vollclient ausgeführt werden kann ([mehr über das Signieren von Code in time cockpit ...](https://www.timecockpit.com/blog/2014/11/27/Why-You-Need-to-Sign-Your-Custom-Code)). In der neuen Version erhalten Sie bessere Informationen über die Ursache eines Fehlers.
